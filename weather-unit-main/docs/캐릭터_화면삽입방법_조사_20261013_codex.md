### 용량 목표와 지연 판단

- [감] 첫 화면에 카드 애니메이션 1개와 정지 전신 몇 개만 표시한다면, **캐릭터 관련 초기 전송량 0.5MB 이내**, 동작 카드 **0.1~0.25MB 이내**, 전체 대시보드 초기 전송량 **1~2MB 이내**를 출발 목표로 제안한다. 모두 팀 내부 예산안이고 네트워크 보증값은 아니다.
- [측정] 겨울 MP4 68,845B + WebP 포스터 15,470B + 겨울 전신 1× WebP 20,076B = 104,391B. 브라우저가 포스터와 영상을 모두 받는 최악의 단순 합산이다. 원본 MP4+원본 포스터+원본 전신은 2,432,844B이므로 같은 장면에서 리사이즈·분리 전송의 의미가 크다.
- [감] 모바일 4G에서도 실제 대기시간은 신호·서버 응답·캐시·동시 요청·영상 자동재생 정책에 좌우된다. 숫자 목표는 Chrome/Edge 모바일 에뮬레이션과 실제 휴대폰에서 최초 방문/재방문 네트워크 전송량, LCP, 카드 표시 시각을 보고 재조정한다. [web.dev LCP 안내](https://web.dev/articles/optimize-lcp)는 좋은 LCP를 2.5초 이내로 제시하지만 이 프로젝트의 실측 성능은 아직 없다.
- [조사 URL] [GitHub 파일 크기 제한](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github): 일반 Git에서 50MiB 초과는 경고, 100MiB 초과는 차단, 웹 업로드는 25MiB 제한이다. 이번 시험 파일은 모두 그보다 작다. 이 한계는 웹 페이지 속도 기준이 아니다.

### Spring Boot + Thymeleaf에 붙이는 계약

1. [조사 URL] [Spring Boot 정적 파일·템플릿 위치](https://docs.spring.io/spring-boot/4.0/reference/web/servlet.html): `src/main/resources/static/weather/...` 아래 파일이 URL `/weather/...`로 제공되고, 화면은 `src/main/resources/templates/`에서 읽는다. 캐릭터용 외부 API 등록은 필요 없다. 이미지·영상은 정적 URL로 받아 브라우저가 그린다.
2. [파일][조사 URL] 기존 빈 `templates/components/weather-card.html`에 활동 카드 fragment를 두고 `dashboard/index.html`에서 넣는 방향이 구조도와 맞다. [Thymeleaf 공식 튜토리얼](https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html)의 `@{...}`는 컨텍스트 경로를 반영하고 `~{...}`는 fragment를 넣는다. 아래는 **팀이 구현할 때의 예시**이며 현재 앱에 붙인 결과가 아니다.

```html
<div th:replace="~{components/weather-card :: activityCard(${activity})}"></div>
<!-- weather-card.html 안 -->
<section th:fragment="activityCard(activity)" class="activity-card">
  <p th:text="${activity.title}">겨울 활동</p>
  <img class="scene-fallback"
       th:src="@{/weather/winter/winter_poster_230x256.webp}"
       alt="눈길에서 웅크린 캐릭터와 햄스터가 추워하는 모습">
  <video class="scene-motion" autoplay muted loop playsinline preload="none"
         th:poster="@{/weather/winter/winter_poster_230x256.png}"
         aria-hidden="true">
    <source th:src="@{/weather/winter/winter_card_230x256_h264.mp4}" type="video/mp4">
  </video>
  <p th:text="${activity.reason}">낮은 기온으로 따뜻한 복장을 권합니다.</p>
</section>
```

   [감] 실제 코드에서는 서버가 허용 목록으로 상태 키를 정적 경로에 매핑해야 한다. 사용자 입력을 파일 경로에 그대로 이어 붙이지 않는다. 초기에는 포스터/문구를 표시하고 영상이 재생될 때만 영상으로 전환하며, `play()` 거절·load 오류면 포스터와 문구를 유지한다. `prefers-reduced-motion: reduce`에서는 영상 source를 요청하지 않거나 재생을 멈추고 포스터를 유지한다. [MDN video](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video), [MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion).
3. [파일][감] 첫 페이지는 MVC가 상태 키·날씨 수치·추천 문구를 Model에 담아 렌더링한다. 지역/날짜 변경은 REST JSON으로 `{date, region, themeKey, activityKey, outfitKey, discomfortStage, text, assetUrl}` 같은 작은 상태를 보낸다. 프론트는 마지막 요청만 반영하고 카드 텍스트와 미리 준비된 정적 URL을 갱신한다. 이미지 바이트를 JSON/base64에 넣을 이유가 없다.
4. [감] DB가 필요하다면 예보·추천 이력과 채택된 상태 키 또는 버전 관리용 경로만 저장한다. 캐릭터 그림 자체는 정적 파일로 둔다. 외부 CDN/오브젝트 저장소는 다수 이미지와 대량 트래픽이 생겼을 때 재검토할 옵션이다. 지금 파일 수·크기·수업 범위에는 근거가 없다.
5. [파일] FastAPI는 기온 추론을 맡는다. 캐릭터 선택은 Spring 추천/테마 결과를 반영하므로 캐릭터 제공용 별도 API는 필요하지 않다. `build.gradle`의 웹 의존성과 datasource 미설정은 팀에 확인할 사항이며 이 조사에서 앱은 수정하지 않았다.

## 날씨 데이터 → 캐릭터 키 초안

[파일][감] 기상청 하늘/강수/시각에서 테마-01을 선택하고, AI 기온과 KMA 습도의 같은 지역·유효시각 값으로 계산한 DI 단계는 **별도 표정 상태**로 둔다. 추천-02의 옷은 기온과 팀 규칙으로 고른다. 날씨 테마, 표정, 옷, 활동은 각각 다른 키이며 모든 조합의 영상을 만들 필요는 없다. 강수에서 눈 > 비, 다음 밤 > 흐림 > 맑음 같은 우선순위는 제안일 뿐 팀이 정해야 한다. 데이터 누락이면 기본 정지 그림과 설명을 쓴다.

| 용도/키 초안 | 선택 입력 | 지금 있는 자료 | 빠진 것 |
|---|---|---|---|
| `base` | 자료 누락·기본 | 기준 캐릭터 정지 PNG | 기본 배경/아이콘 연결 |
| `cloudy`, `rain`, `snow`, `night` | KMA 하늘·강수·시각 | 목업의 CSS 비 효과만 참고 가능 | 채택된 독립 캐릭터/배경/아이콘 미제작 |
| `summer_hot` | 기온·복장 규칙 | 여름 캐릭터 정지 PNG | 더위 표정·활동 동작 |
| `winter_cold` | 기온·활동/복장 규칙 | 겨울 착장 정지 PNG, 추위 카드 MP4/포스터, 아이템 PNG | 다른 활동/표정 |
| `di_normal/caution/high/very_high` | 불쾌-02 단계(명세서 68/75/80 경계 확정 필요) | 전용 단계별 표정 없음 | 단계별 표정 또는 텍스트 대체 |

## 접근성·실패 시 표시

- [파일][조사 URL] 테마-02와 공통-01에 맞춰 동작은 선택 사항으로 두고, `prefers-reduced-motion`이면 포스터만 표시한다. 자동재생이 거절되거나 영상 디코딩이 실패해도 활동명·추천 이유·날짜·자료 상태 글은 남긴다. [MDN 모션 감소](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion), [MDN 자동재생](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay).
- [감] 정보가 있는 정지 그림에는 구체적인 `alt`를 붙이고 장식용 반복 영상은 `aria-hidden="true"`로 둔다. 클릭 가능한 복장 캐릭터는 `<button>`과 보이는 이름·키보드 초점을 사용한다. 이미지가 실패해도 대체 텍스트와 카드 문구가 의미를 전달하게 한다.
- [감] 무한 반복 GIF/WebP/APNG는 CSS만으로 확실히 정지시키기 어려워, 모션 감소/재생 제어가 필요한 핵심 카드는 비디오와 별도 포스터가 관리하기 쉽다.
