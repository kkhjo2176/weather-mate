우리 캐릭터를 카드 박스에 넣는 방법

Codex 조사(감독메모 M24)를 제가 다시 재고 화질을 눈으로 비교했습니다. 맞는 것, 고친 것, 아직 모르는 것을 나눠 적었습니다.

결론가능합니다. 박스는 HTML(Thymeleaf), 캐릭터는 MP4 영상 + 정지 그림 파일로 넣는 게 가장 작고 깨끗합니다.
파일 크기카드 1개 = 약 160KB (휴대폰 선명도 기준). 원본 그대로 넣으면 약 2.4MB.
API캐릭터 전용 API는 필요 없습니다. 서버는 winter_cold 같은 이름만 보내고, 화면이 그 이름의 파일을 엽니다.
GIFMP4보다 3배 크고 화질이 거칩니다. 안 쓰는 걸 추천합니다.

재검토 결과

  • 맞음시험 파일 16개 크기를 디스크에서 다시 재 보니 보고서와 모두 같았습니다. MP4는 230×256 · 24fps · 86프레임 · 3.58초로 원본 길이와 같습니다.
  • 맞음"캐릭터 전용 API 불필요"는 아키텍처와 맞습니다. 그림 속 구조가 "첫 화면은 HTML, 이후엔 JSON으로 영역만 갱신 · 파일은 static"입니다.
  • 맞음GIF 화질 문제를 눈으로 확인했습니다(위 확대 그림).
  • 고침Codex는 1배 크기(230×256)만 쟀습니다. 요즘 휴대폰은 화면이 2~3배 촘촘해서 1배 영상은 흐려 보입니다. 2배로 다시 재니 MP4 119KB + 정지 그림 42KB = 약 160KB입니다. 여전히 GIF 1배보다 작습니다.
  • 고침보고서의 예시 코드는 정지 그림과 영상이 동시에 보이게 되어 있고, 정지 그림을 작은 WebP(15KB) 대신 큰 PNG(115KB)로 부르고 있습니다. 팀에 넘길 때는 제가 고친 예시로 드리겠습니다.
  • 감"화면 하나에 캐릭터 파일 0.5MB 이내"는 Codex가 제안한 목표입니다. 공식 기준은 아니지만 지금 크기면 여유 있게 들어갑니다.
  • 못 함실제 휴대폰 재생, 팀 앱에서 화면 띄우기는 시험하지 못했습니다. 팀 앱은 아직 빈 틀이고, 웹 서버 의존성과 DB 접속 설정이 빠져 있어 그대로는 안 뜰 가능성이 큽니다. 팀에 알릴 일입니다.

화면에 들어가는 흐름

1. 날씨 판단Spring이 기온·하늘·불쾌지수로 상태를 고름
→
2. 이름만 전달winter_cold
→
3. 카드 박스Thymeleaf 카드 조각(weather-card.html)
→
4. 우리 파일static/weather/winter/…mp4 · webp

팀원이 박스 자리에 넣을 코드 예시(제가 고친 판). 모션 줄이기 설정이나 재생 실패 때는 정지 그림이 남습니다.

<div class="weather-card">
  <video autoplay muted loop playsinline
         th:poster="@{/weather/winter/winter_cold_poster@2x.webp}"
         aria-label="눈길에서 웅크리고 추워하는 캐릭터">
    <source th:src="@{/weather/winter/winter_cold@2x.webm}" type="video/webm">
    <source th:src="@{/weather/winter/winter_cold@2x.mp4}"  type="video/mp4">
  </video>
  <p th:text="${activity.reason}">기온이 낮아요. 따뜻하게 입으세요.</p>
</div>

예시일 뿐, 팀 앱에 붙여 실행한 결과는 아닙니다. 파일 이름은 납품 때 확정합니다.

팀에 물어볼 것

  1. 백엔드: 화면에 보낼 상태 이름을 어떤 규칙으로 정할지 (예: winter_cold, rain)
  2. 프론트: 캐릭터 박스의 실제 크기 (휴대폰 / PC)
  3. 팀 전체: 날씨·불쾌지수·복장 중 무엇이 캐릭터를 우선 결정하는지
  4. 프론트: 지원할 휴대폰·브라우저 범위
  5. 팀 전체: 어떤 시안을 채택할지, weather-unit에서 파일을 누가 옮길지
